## Goal

The honesty companion to 8.3's validation report: a standalone, **cited** statement of
*how accurate SGP4-on-public-elements actually is*, so OrbitWatch claims exactly what it
can back — an honest **geometric screener**, not operational collision avoidance. The
differentiator vs. a typical portfolio project: most *assert* "SGP4 is ~1 km"; we
**measured the dominant error empirically in 8.3** (epoch drift) and cite authorities for
the rest.

---

## Approach

- **Doc-only, hand-authored Markdown** (`validation/sgp4_uncertainty.md`) — not
  regenerated by the runner, so it won't be clobbered; linked from the report + (future)
  README. No new measurement script (8.3 already measured the dominant term).
- **Separate the three error sources** that are routinely conflated: (1) our SGP4
  implementation (verified < 1 m), (2) element accuracy at epoch (~1 km), (3) growth with
  age (~2–3 km/day) + (4) epoch drift from stale public elements — the term that
  dominates in practice and the one we measured.
- **Citations verified first, never fabricated.** Confirmed each source/figure via the
  web before writing; attributed each claim to the *correct* source.

## Validation

- **Citations confirmed (web-verified, attributed correctly):**
  - **MathWorks *Satellite Conjunction Finder*** — uses TLE/SGP4 + `fzero` root-finding on
    the inter-satellite distance derivative (the **same method** as our range-rate Newton),
    and carries the verbatim disclaimer *"Do not use publicly available TLEs for
    operational conjunction assessment prediction… contact the 18th Space Defense Squadron."*
  - **NASA/SP-20205011318** — *Spacecraft Conjunction Assessment and Collision Avoidance
    Best Practices Handbook*, Krage, 2020 (NTRS) — the screening-vs-operational authority.
  - **Vallado et al., AIAA 2006-6753** (*Revisiting Spacetrack Report #3*) — cited
    **correctly** for *implementation* fidelity (what we cross-validate against), NOT for
    element accuracy (a distinction the doc makes explicit).
  - **~1 km at epoch / ~2–3 km/day** — the documented consensus (Skyfield/Rhodes +
    CelesTrak), and corroborated by our own measured numbers.
- **Evidence-backed, not asserted:** the doc's §4 cites our 8.3 result directly —
  current-feed median |Δmiss| **1.13 / 2.58 / 2.51 km** (ISS / top-25 / Starlink-40),
  reproduction degrading with `DSE`, → **0.000 km** and 89–100 % when epoch-matched. The
  kilometers are epoch drift, measured and recoverable.

## Lessons learned

- **STR#3 ≠ TLE accuracy.** *Revisiting Spacetrack Report #3* establishes that an SGP4
  *implementation* reproduces the reference code (sub-meter) — it is **not** a statement
  about how accurate the element *sets* are. Easy to miscite; the doc keeps the two
  separate (implementation fidelity in §2, element accuracy in §3).
- **Our 8.3 data is the strongest citation in the doc.** "We measured public-element
  epoch drift at 1–3 km median, and it vanishes on the matched element" beats any quoted
  figure — it's original and reproducible.
- **Keep generated + committed artifacts in sync without a live regen** — editing the
  generator *and* the committed report (rather than re-running) preserved the exact 8.3
  numbers the doc cites, avoiding a current-feed drift that a regen would introduce.
